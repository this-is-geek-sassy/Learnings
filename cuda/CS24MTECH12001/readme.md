# CUDA Assignment Directory Structure and Program Usage

## Directory Structure

- `build.sh` — Bash script to compile all CUDA source files.
- `checker.py` — Python script to validate output files and directory structure for assignment submission.
- `main_1_1.cu` — CUDA C++ source for Assignment 1.1 (Matrix Multiplication, CPU & GPU).
- `main_1_2.cu` — CUDA C++ source for Assignment 1.2 (Matrix Multiplication, CPU & GPU, but Kernel launch using 2D params).

- `main_2.cu` — CUDA C++ source for Assignment 2 (Matrix Multiplication with Tiling, CPU & GPU).

- `main_3.cu` — CUDA C++ source for Assignment 3 (Basic Version of Matrix Transpose).
- `main_4.cu` — CUDA C++ source for Assignment 4 (Matrix Transpose with tiling, CPU & GPU).

- `report.pdf` — Assignment report.
- `public_test_cases/` — Folder containing test input and output CSV files:
    - `matrix_a.csv`, `matrix_b.csv`, `matrix1.csv`, `matrix2.csv`, `i_5.csv` — Input matrices.
    - `output_*.csv` — Expected output matrices for test cases.
    - `output_*.txt` — Kernel execution time outputs for test cases.
- `target/` — Compiled binaries and results:
    - `main_1_1`, `main_1_2`, `main_2`, `main_3`, `main_4` — Compiled executables.
    - `results/` — Output CSVs generated by the programs.

## Program Usage and Command Line Arguments

All CUDA programs expect command line arguments as follows:

### main_1_1.cu
**Usage:**
```
./main_1_1 <block_size> <path_to_matrix_a> <path_to_matrix_b>
```
- `<block_size>`: Block Size, i.e., #Threads in a block.
- `<path_to_matrix_a>`: Path to first input matrix CSV file.
- `<path_to_matrix_b>`: Path to second input matrix CSV file.

### main_1_2.cu
**Usage:**
```
./main_1_2 <block_size_x2> <block_size_y2> <path_to_matrix_a> <path_to_matrix_b>
```
- `<block_size_x2>`: x dimension of 2D Block Size, i.e., #Threads in a block in x dim. (integer).
- `<block_size_y2>`: y dimension of 2D Block Size, i.e., #Threads in a block in y dim. (integer).
- `<path_to_matrix_a>`: Path to first input matrix CSV file.
- `<path_to_matrix_b>`: Path to second input matrix CSV file.

### main_2.cu
**Usage:**
```
./main_2 <tile_m> <tile_n> <path_to_matrix_a> <path_to_matrix_b>
```
- `<tile_m>`: Tile size for rows (integer).
- `<tile_n>`: Tile size for columns (integer).
- `<path_to_matrix_a>`: Path to first input matrix CSV file.
- `<path_to_matrix_b>`: Path to second input matrix CSV file.

### main_3.cu
**Usage:**
```
./main_3 <block_size> <path_to_matrix_a>
```
- `<block_size>`: Block Size, i.e., #Threads in a block.
- `<path_to_matrix_a>`: Path to the input matrix CSV file.

### main_4.cu
**Usage:**
```
./main_4 <tile_m> <tile_n> <path_to_matrix>
```
- `<tile_m>`: Tile size for rows (integer).
- `<tile_n>`: Tile size for columns (integer). (in general for this program, you may give rectangular tiles also.)
- `<path_to_matrix>`: Path to input matrix CSV file to be transposed.

## Output Files
- Each program writes its result matrix to a CSV file named `output_X_CS24MTECH12001.csv` (where X matches the assignment part) in the current or results directory.
- GPU kernel execution time is written to a corresponding `output_X_CS24MTECH12001.txt` file.

## Notes
- All programs prompt for CPU/GPU selection at runtime.
- Input matrices must be in CSV format.
- See `checker.py` for output validation requirements.
